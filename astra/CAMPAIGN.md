# Autonomous search jobs

Requires Python 3.10+, SymPy and PARI/GP. Test with `ASTRA_GP=$(command -v gp) python -m unittest -v`. No GPU or network needed. Local GP was PARI 2.17.4. For a VM with GP on PATH, copy this whole directory, install the dependencies, and run `timeout 1h bash vm-pilot.sh`. Use a cloud-side shutdown/budget limit too: a shell timeout does not stop VM billing. Resume with the same invocation and files. Only one launcher per output directory. Inspect `worker-*.log` on nonzero exit.

## Anchored manifests

`runs/anchor-v1/jobs.json` was generated with `python campaign.py make ...` (default parameters). Four workers: `python campaign.py run MANIFEST shard-I.jsonl --shards 4 --shard I --gp /path/to/gp`. Each completed job logs the manifest hash, anchor, family, width, elapsed seconds, logical odd subset count, and numbers passing the anchor, second, and full conditions above 2^64. Counts across constructions can overlap; within one manifest/family different anchors are disjoint. Counts of subsets are not counts of primality-test calls. Keep the manifest and receipts together. On restart, completed jobs are skipped; the interrupted job is replayed. If an abrupt kill leaves a torn final JSON line, save a backup and truncate only that final partial line before resuming. `python campaign_status.py runs/*/*.jsonl` summarizes receipts and flags candidate records.

- `paper`: 39 smallest paper-family primes with one mandatory larger paper prime. Every nonempty even subset of the core is represented.
- `5`, `-7`: inert primes grouped by 2-part of order and Lucas rank. For -7 require each prime to be +1 in the (5/p) symbol, so an odd subset actually selects Selfridge D=-7. Greedily grow mutually compatible cores with shared order/rank factors. These are selected cores, **not** exhaustive prime ranges. A fixed anchor p forces the product w of the other factors to be 1 modulo lcm(order_p,rank_p). Join two subset tables on this condition. Check surviving products against each remaining factor, largest first. Exact congruences plus matching 2-parts synchronize strong tests. Every full candidate is saved, tested with SymPy, and passed to the independent `verify.gp`; only a confirmed `VERDICT=1` is a hit.
- `anchor-v2` is D=5, width 41, 20000 < anchor <= 30000. `vm-pilot.sh` assigns 30000 < anchor <= 40000, disjoint from v2 and the v1 exact-order D=5 sweep. Do not launch duplicate VM pilots; assign new nonoverlapping anchor intervals if expanding. The paper family is separate and can overlap. Manifest generation deterministic for the same SymPy/Python code; distribute one manifest if splitting a campaign across machines.

## GCD completion

For selected inert p,q with compatible periods, w=pq. Any inert prime r>q completing a hit must satisfy ord_r(2)|w-1 and rank_r(U)|w-1 since these periods divide r-1 and r+1 respectively. Thus r divides gcd(2^(w-1)-1,U_(w-1)). `gcd_scan.gp` computes this integer exactly for D=5,-7, factors it if large enough, and proves primality of returned divisors. This removes the upper bound on r but not restrictions on the two-prime prefix or discriminant. The prefix congruences and both strong tests are checked in Python; any hit is reverified in GP. Example: `python gcd_scan.py shard-0.jsonl --D 5 --lower 100000 --bound 2000000 --shards 2 --shard 0`. Logs resume on completed batches; keep parameters/code constant. Local logs are under `runs/gcd-v1/`. Distinguish a completed bounded campaign from resolution of the open problem.
