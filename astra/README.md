# Astra: search for a strong Baillie–PSW counterexample

**Status: no verified counterexample.** Start with [the agent handoff](HANDOFF.md) for exact search domains, results and next steps. [SCALE_NEXT.md](SCALE_NEXT.md) describes the order catalogue; [KERNEL_LIFTS.md](KERNEL_LIFTS.md) covers the dense-pool approach. The reports under `runs/` are scoped computational evidence, not a proof that the test has no counterexample.

## Local setup

From `astra/`, use Python 3.14 (tested), a C++20 compiler, GNU Make, GMP development headers/libraries and PARI/GP on PATH. No VM is needed.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
make -j2 native
make test
```

Use `make test GP=/path/to/gp` for a nonstandard PARI installation; set `LD_LIBRARY_PATH` if its shared library is also nonstandard. The Makefile builds local `rank_divisors` and `triple_orders`; pass `--bin ./rank_divisors` or `--bin ./triple_orders` to use them in the latest search scripts instead of `/tmp` builds. The repository includes the catalogue inputs and final results needed for the handoff. Bulky historical VM worker logs, local binaries and live monitoring state are not versioned. The `iris_*.sh` and `vm-*.sh` scripts are historical infrastructure, not setup steps.

## Original D=5 discovery pilot

From `astra/`:

```sh
python -m unittest -v
python search.py discover --limit 1000000 --trials 3000 --smooth 127 --seed 1 --out pools-1.json
python sweep.py pools-1.json
python search.py profile pools-1.json --pool 5419
```

Pilot: 39,286 eligible primes; 5,440 pools; 423,352 odd subsets of size >=3 **counted with overlap**; no counterexample. Discovery took ~9 s on the development host. Largest pool: 15 factors. Pool 5419's target is not even in the group generated by its factors with parity, so increasing subset-search throughput for it cannot help.

**Construction.** For each odd prime p = 2 or 3 mod 5, strip prime divisors from p-1 and p+1 to find ord_p(2) and the Fibonacci rank of apparition. Assign small odd prime powers randomly to two coprime sides, allowing powers of two with gcd at most 2. Retain orders/ranks dividing those templates, group by the two 2-adic valuations, and shrink templates to actual LCMs A,B. Search for odd subsets of distinct primes with product 1 mod A and -1 mod B. Odd cardinality forces Selfridge D=5. Equal order valuations synchronize the Miller–Rabin branches. Equal rank valuations synchronize the strong Lucas branches because F_(2k)=F_k L_k: at the first doubling where the Fibonacci term vanishes, the preceding Lucas term vanishes. Each CRT hit is retested on the full product by SymPy; its factors certify compositeness. These conditions are sufficient, not necessary for a BPSW counterexample.

**Scale discovery first.** Run distinct `--seed` values in separate processes, with separate output files. Seeds can overlap; pools and subsets are not globally deduplicated. The sieve uses memory linear in `--limit`, and each trial scans the catalogue. The discovery ranking is a cheap proxy, not a probability estimate. `profile` uses prime-power unit group coordinates and lattice indices for exact subgroup size and membership, including odd parity. A negative result rules out a pool; a positive result allows arbitrary integer exponents, not necessarily 0/1. Prefer pools with reachable targets and many subsets relative to group size. If templates stay sparse, change pool generation rather than pouring CPUs into bigger subset tables.

**Shard a promising pool.** Workers must use the same JSON file, pool index, and `--left L`. Partition `[0, 2^(number_of_factors-L))` into disjoint intervals. Example for the pilot's 15-factor pool (demonstration only):

```sh
python search.py search pools-1.json --pool 5419 --left 7 --start 0 --end 128
python search.py search pools-1.json --pool 5419 --left 7 --start 128 --end 256
```

Each process builds its own 2^L-entry Python hash table and streams the right interval in Gray order. Start with L <= 18 and measure resident memory before raising it. For small pools `sweep.py` is simpler. Keep pool JSON, parameters, shard intervals and stdout for reproducibility. Any reported hit should be confirmed with an independent implementation before publication.
